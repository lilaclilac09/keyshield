五个旋钮，全部拧到底

把这个场景想象成给一辆赛车调校。引擎（算法）在做它的事，但轮胎、空气动力、维修站的换胎编排同样至关重要。这份代码里拧的正是这五个旋钮。

🛣️

HTTP/2 多路复用

只开一条 TLS 连接，在上面跑许多并行请求。省掉反复握手的代价。

🗜️

Gzip + Brotli

JSON-RPC 响应能压到 5–10 分之一。直接让服务端发压缩字节。

🚦

并发上限

一个容量 100 的信号量，避免把 Helius 冲垮招来限流。

🔁

指数退避

遇到 429 / 5xx 就重试，每次等待时间翻倍。最多 5 次。典型的生产级模式。

🔥

连接预热

在真正开工之前先发一个无关痛痒的小请求，把 TLS 握手的代价从主路径上挪开。

HTTP 客户端一次性配置好

上面五个旋钮，都活在同一段代码里。把这段 builder 当成一张决策清单来读。

rpc.rs — HeliusClient::new 
let client = Client::builder()
    .http2_adaptive_window(true)
    .http2_initial_stream_window_size(2 * 1024 * 1024)
    .http2_initial_connection_window_size(16 * 1024 * 1024)
    .tcp_nodelay(true)
    .pool_max_idle_per_host(100)
    .pool_idle_timeout(Duration::from_secs(90))
    .timeout(Duration::from_secs(30))
    .gzip(true)
    .brotli(true)
    .build()
    .expect("failed to build HTTP client");
大白话

那两个大窗口值（每流 2MB、每连接 16MB）是在告诉 HTTP/2："别用流控卡我。"默认值是为小响应优化的；我们这里是胖胖的交易数据页。

tcp_nodelay 关闭 Nagle 算法，让小请求不至于在缓冲区里干等着凑一批。

保留最多 100 条空闲连接，空闲 90 秒内不回收，这样后续请求就能跳过 TLS 握手。

gzip 和 brotli 告诉 Helius 压缩回包。2MB 的 JSON 响应能以 200KB 的体量到达。

预热：给引擎打火

在真正开工之前，main.rs 做了一件看起来毫无意义的事。

main.rs 
let (_, balances) = tokio::try_join!(
    client.warm(),
    algorithm::compute(&client, &args.address),
)?;
大白话

它让 warm()（一个微型空调用）和真正的计算并行运行。

warm() 会打开 TCP + TLS + HTTP/2 连接，并向服务端 ping 一个无关紧要的请求。这些"没劲"的工作，否则会堆在第一次真实请求之前，把几毫秒硬加到关键路径上。

用 try_join! 两者同时跑，握手在后台进行的时候，算法已经在做它自己的准备工作。真正的拉取落在一条已经热起来的连接上。

优雅的重试

网络会抖，服务器会过载。生产级客户端会重试 —— 但必须聪明地重试。

rpc.rs — the retry loop 
for attempt in 0..5u32 {
    let http = self.client.post(&self.rpc_url)
        .json(&request).send().await?;
    let status = http.status();
    if status == 429 || status.is_server_error() {
        if attempt < 4 {
            let ms = 100 * 2u64.pow(attempt);
            tokio::time::sleep(Duration::from_millis(ms)).await;
            continue;
        }
        bail!("HTTP {status} after {attempt} retries");
    }
    ...
}
大白话

最多重试 5 次。每次比上次睡得久：100、200、400、800 毫秒。这就是指数退避。

只对值得重试的错误重试：429（限流）和 5xx（服务端抽风）。不要对 4xx 重试 —— 那是你自己做错了，再试多少次也不会对。

循环里还专门对 Solana 自定义的 RPC 错误码 -32429 重试，这是 Helius 在 JSON-RPC 包体里（不是在 HTTP 层）表示限流的方式。

💡
通用模式

带次数上限的指数退避，是任何生产客户端对任何不稳定依赖（数据库、支付网关、其他内部服务）的标准重试配方。你要是让 AI 写网络代码，就说"用 5 次上限的指数退避，只在 429 和 5xx 时重试"。
