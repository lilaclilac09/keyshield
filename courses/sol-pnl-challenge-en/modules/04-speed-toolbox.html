The Speed Toolbox

A guided tour of the small-but-important tuning knobs that turn "fast enough" into "sub-500ms." Each one is a pattern you can ask AI to apply to your own network code.

Five dials, all turned up

Imagine tuning a race car. The engine (the algorithm) is doing its thing, but the tires, the aerodynamics, and the pit-stop choreography matter just as much. These are the five dials this codebase turns to shave milliseconds.

🛣️

HTTP/2 multiplexing

Open one TLS connection and run many parallel requests over it. No repeated handshake cost.

🗜️

Gzip + Brotli

JSON-RPC responses compress 5–10x. Ask the server to send compressed bytes.

🚦

Concurrency cap

A 100-slot semaphore stops the program from flooding Helius and getting rate-limited.

🔁

Exponential backoff

Retry on 429 / 5xx, doubling the wait each time. Five tries max. Typical production pattern.

🔥

Connection warm-up

Fire a tiny throwaway call before the real work so the TLS handshake isn't on the hot path.

The HTTP client, configured once

Every one of those five dials lives in a single block of code. Read the builder like a checklist of decisions.

rpc.rs — HeliusClient::new 
let client = Client::builder()
    .http2_adaptive_window(true)
    .http2_initial_stream_window_size(2 * 1024 * 1024)
    .http2_initial_connection_window_size(16 * 1024 * 1024)
    .tcp_nodelay(true)
    .pool_max_idle_per_host(100)
    .pool_idle_timeout(Duration::from_secs(90))
    .timeout(Duration::from_secs(30))
    .gzip(true)
    .brotli(true)
    .build()
    .expect("failed to build HTTP client");
PLAIN ENGLISH

The big window sizes (2MB per stream, 16MB per connection) tell HTTP/2 "don't choke me with flow control." Defaults assume tiny responses; ours are fat transaction pages.

tcp_nodelay disables Nagle's algorithm so small requests don't sit in a buffer waiting for more bytes to batch.

Keep up to 100 idle connections alive for 90 seconds so subsequent requests skip the TLS handshake entirely.

gzip and brotli ask Helius to compress its replies. A 2MB JSON response can arrive as 200KB of bytes.

The warm-up: priming the engine

Before the real work starts, main.rs does something that looks pointless.

main.rs 
let (_, balances) = tokio::try_join!(
    client.warm(),
    algorithm::compute(&client, &args.address),
)?;
PLAIN ENGLISH

It runs warm() — a tiny dummy call — in parallel with the real computation.

warm() opens the TCP+TLS+HTTP/2 connection and pings the server with a trivial request. That "boring" work would otherwise happen on the first real request and tack extra milliseconds onto the critical path.

By running both together with try_join!, the handshake completes in the background while the algorithm is doing its own setup. The real fetches land on an already-hot connection.

Retries done right

Networks fail. Servers get overloaded. A production-grade client retries — but smartly.

rpc.rs — the retry loop 
for attempt in 0..5u32 {
    let http = self.client.post(&self.rpc_url)
        .json(&request).send().await?;
    let status = http.status();
    if status == 429 || status.is_server_error() {
        if attempt < 4 {
            let ms = 100 * 2u64.pow(attempt);
            tokio::time::sleep(Duration::from_millis(ms)).await;
            continue;
        }
        bail!("HTTP {status} after {attempt} retries");
    }
    ...
}
PLAIN ENGLISH

Try up to 5 times total. On each retry, sleep longer than the last: 100ms, then 200, 400, 800. This is exponential backoff.

Only retry on the errors that are worth retrying: 429 (rate-limited) and 5xx (server having a bad day). Don't retry on 4xx — those mean you did something wrong and retrying won't fix it.

The loop also specifically retries on Solana's custom RPC error code -32429, which is how Helius signals rate-limiting inside the JSON-RPC envelope (not at the HTTP layer).

💡
Universal pattern

Exponential backoff with a cap on attempts is the standard retry recipe for any production client talking to any flaky dependency — databases, payment processors, other internal services. If you're ever asking an AI to write network code, say "use exponential backoff with 5 max attempts, only retry on 429 and 5xx."
