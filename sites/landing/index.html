Give your agents access, not your API keys.

KeyShield is a vault for provider keys. Keys are encrypted on your device, agents get a scoped session token instead, and every call goes through a proxy that adds the real key for that one request. You can revoke an agent at any time.

The problem

Pasting a key into an agent means handing it over for good.

Raw keys in .env files get copied across machines, tools and teammates. Taking access away means rotating the key at the provider and breaking everything else that uses it.

Today: raw keys in every process

  • The agent holds the same key you do, with all of your access.
  • Keys end up in logs, traces, prompt context and screenshots.
  • To cut off one agent, you rotate the key and update every consumer.
# agent/.env
OPENAI_API_KEY=sk-proj-…
ANTHROPIC_API_KEY=sk-ant-…

With KeyShield: one token per agent

  • The agent holds a session token. The provider key stays in your vault.
  • The key is decrypted for one upstream request and isn't written to disk or logs.
  • Revoke one agent and its next request gets a 401. Nothing else breaks.
# agent/.env
KS_TOKEN=<session token, revocable>
KS_BASE=https://keyshield-production.up.railway.app
How it works

Store a key once. Hand out tokens instead.

One vault with two ways in: a dashboard and browser extension for you, and an SDK, CLI and REST API for your agents.

01

Unlock with a passkey

Face ID, Touch ID or another WebAuthn passkey unlocks your vault. The encryption key is derived on your device from the passkey's PRF output.

02

Save your provider keys

Paste a key, or let the browser extension catch it on the provider's page. It's encrypted with AES-256-GCM before it leaves the browser.

03

Give each agent a token

Copy a session token from Developer, or register an agent's ed25519 key so it can sign in by itself. Either way it only gets the token.

04

Call through the proxy

Point the client's base URL at KeyShield. The proxy checks the token, adds the key and forwards the call. Revoke whenever you want.

Features

Everything on this list is in the repo.

Each feature links to the code or doc it comes from, so you can check it yourself.

Client-side encryption

Passkey PRF output (or a wallet signature) goes through HKDF-SHA256 to an AES-256-GCM key. The server stores ciphertext, nonce and tag only.

SPEC.md §3 →

Scoped session tokens

Agents get a bearer token scoped to a provider, with an expiry. The raw sk- key never enters the agent's process.

SPEC.md §4 →

Revocation on the next request

Tokens are checked on every proxy call, with no cache window. Revoke one session or agent from the dashboard, API or MCP, and its next call fails.

SPEC.md §7 →

Agent identities

Register an agent's ed25519 public key. The agent signs a server challenge to get its own token, and the server never stores its private key.

How agents register →

Drop-in proxy

Proxy paths for OpenAI, Anthropic, OpenRouter, Groq, Mistral, Cohere and Helius. Any client that takes a base URL and a bearer token works without code changes.

docs/API.md →

Browser extension

The Chrome extension spots API keys on provider pages and saves them to your vault in one tap. You can also use it to fill keys back into settings pages.

Install guide →

MCP server for Claude

List providers, sessions and agents, and revoke any of them, straight from Claude. The MCP tools never return raw keys.

packages/mcp-server →

SDK and CLI

A Python SDK with sync and async clients and ready-made OpenAI and Anthropic clients. The CLI's keyshield run -- <cmd> works like op run.

packages/sdk-py →

Read-only RPC cache

The Rust proxy caches read-only Solana RPC calls like getBalance in memory and on disk. Identical requests in flight share one upstream call.

src/proxy →

Scoped sharing

Grant a teammate access to one stored key, and revoke that share on its own later. Shares are tied to a key name, so you control access per key.

docs/API.md →

Pay per call on Solanadevnet

Optional metering: funds are held first, the upstream response is checked, and only then is the call settled. An empty or failed response can't be charged.

Security model

What each part of the system can see.

KeyShield is built so the server can't read your keys at rest, and agents never see them at all. This is where each secret lives.

your device
Plaintext key exists here. Encrypted locally before upload.
WebAuthn PRFHKDF-SHA256AES-256-GCM
vault storage
Ciphertext only. The sync worker stores encrypted blobs. Without your device credential it can't decrypt them.
{ ciphertext, nonce, tag }
agent process
Session token only. No sk-, sk-ant- or gsk_ material, and a token can be revoked on its own.
Bearer <session>
proxy
Key in memory for one request. Checks the token and revocation, adds the key, forwards, then drops it. Never written to disk or logs.
verifyrevocation checkinjectforward
upstream
Sees a normal API call made with your key. Nothing about the provider's API changes.

Revocation without delay

Tokens live server-side with a revoked flag that's checked on every request, so revoking an agent doesn't affect the token it came from.

Not an open proxy

Every proxy path needs a valid session. The hosted demo reports public_unauthenticated_proxy: false.

Limits on runaway agents

Each session has per-second and per-minute spend caps on the proxy, and repeated empty or 5xx upstream responses freeze it. Sign-in routes are rate-limited too.

Tested on failure paths

Fault-injection tests return 502s, dropped connections, empty 200s and truncated JSON from the upstream, and check that nothing gets charged.

Known limits

  • KeyShield only protects calls that go through the proxy. It can't add a key to a binary that never calls it.
  • While the proxy is handling a request, the decrypted key is in its memory. secrecy/zeroize hardening is planned but not yet a dependency.
  • On-chain metering runs on Solana devnet only. The spec is v0.1 and the SDK is alpha.
  • We don't publish latency numbers until they're measured in a named production environment.
Quickstart

First proxied call in about five minutes.

  1. 1

    Open the app

    Sign in at app.ks.aileena.xyz with a passkey, or run it yourself.

  2. 2

    Save a provider key

    Add an OpenRouter key under Vault. OpenRouter keys are free, and so is its :free model.

  3. 3

    Copy your token

    Open Developer and copy the session token. Set it as KS_TOKEN.

  4. 4

    Make the call

    Use any of the snippets here. Your code only ever holds KS_TOKEN.

export KS_TOKEN="<paste from Developer>"
export KS_BASE="https://keyshield-production.up.railway.app"

curl -sS -X POST "$KS_BASE/vproxy/openrouter/api/v1/chat/completions" \
  -H "Authorization: Bearer $KS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"model":"nvidia/nemotron-3-ultra-550b-a55b:free",
       "messages":[{"role":"user","content":"ping"}]}'
import os
from openai import OpenAI

# api_key is your KeyShield session, not the OpenRouter key.
client = OpenAI(
    base_url=os.environ["KS_BASE"] + "/vproxy/openrouter/api/v1",
    api_key=os.environ["KS_TOKEN"],
)

reply = client.chat.completions.create(
    model="nvidia/nemotron-3-ultra-550b-a55b:free",
    messages=[{"role": "user", "content": "ping"}],
)
print(reply.choices[0].message.content)
import OpenAI from "openai";

// apiKey is your KeyShield session, not the OpenRouter key.
const client = new OpenAI({
  baseURL: process.env.KS_BASE + "/vproxy/openrouter/api/v1",
  apiKey: process.env.KS_TOKEN,
});

const reply = await client.chat.completions.create({
  model: "nvidia/nemotron-3-ultra-550b-a55b:free",
  messages: [{ role: "user", content: "ping" }],
});
console.log(reply.choices[0].message.content);

FAQ

Questions people ask first

Can KeyShield read my API keys?+

Not at rest. Keys are encrypted in your browser with a key derived from your passkey (or wallet signature), so the server only stores ciphertext. To make a call, the proxy has to hold the decrypted key in memory for that one upstream request. It never writes the key to disk or logs. If you don't want to trust a hosted proxy with that, run the proxy yourself.

Is it free?+

Yes. KeyShield is open source under the MIT license, and you can run the whole stack on your own machine or servers. You still pay your model providers as usual. Their free tiers, like OpenRouter's :free models, work through KeyShield.

What happens if an agent leaks its token?+

Revoke it under Sessions or Agents, through POST /sessions/{prefix}/revoke or DELETE /agents/{id}, or ask Claude through the MCP server. The token stops working on its next request. Your provider key and your other agents keep working, because the leaked token never contained the key.

Which providers and clients work?+

There are proxy paths for OpenAI, Anthropic, OpenRouter, Groq, Mistral, Cohere and Helius (Solana RPC). Any client that takes a base URL and a bearer token works, including the OpenAI SDK, LangChain, CrewAI, AutoGen and the Vercel AI SDK. Streaming responses pass through as SSE.

Do I need a crypto wallet?+

No. Sign in and unlock with a passkey. A Solana wallet is optional, either for signing in or for the experimental per-call metering, which currently runs on devnet.

How is this different from 1Password CLI or HashiCorp Vault?+

Those tools hand the secret to your process, for example through environment variables with op run. KeyShield never does that. The agent gets a token that can be revoked on its own and is only valid through the proxy. The raw key stays in the vault and the proxy. If you do want op run-style injection, the CLI's keyshield run does it too.

Is it production-ready?+

It's early. The protocol spec is v0.1 and the Python SDK is alpha. Security and fault-injection tests run in CI, but read the known limits and the security write-up before you trust it with high-value keys.
