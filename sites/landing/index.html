    01 · Sign in

    Press play to watch KeyShield collect keys and connect your tools.

    The same job, counted in stepsIllustrative steps from the flow above. Not a timing measurement.

    By hand

    1. Create the key on the provider's page
    2. Copy it somewhere safe
    3. Open each tool's settings and paste it
    4. Paste it again into every agent's .env
    5. To cut one agent off, rotate the key and repeat steps 1–4

    With KeyShield

    1. Create the key. The extension spots it on the page
    2. Click Save to vault
    3. Open the tool's settings. Empty key boxes fill on their own
    4. Give each agent a session token, not the key
    5. To cut one agent off, click Revoke. Nothing else changes

    Works with anything that takes a base URL and a bearer token: OpenAI SDK, LangChain, CrewAI, AutoGen, Vercel AI SDK, Claude via MCP, or plain curl.

    The problem

    Pasting a key into an agent means handing it over for good.

    Raw keys in .env files get copied across machines, tools and teammates. Taking access away means rotating the key at the provider and breaking everything else that uses it.

    Today

    Every process holds the raw key

    • The agent holds the same key you do, with all of your access.
    • Keys end up in logs, traces, prompt context and screenshots.
    • To cut off one agent, you rotate the key and update every consumer.
    OPENAI_API_KEY=sk-proj-…
    ANTHROPIC_API_KEY=sk-ant-…
    With KeyShield

    Each agent holds its own token

    • The agent holds a session token. The provider key stays in your vault.
    • The proxy adds the key to each upstream request. The agent never sees it.
    • Revoke one agent and its next request gets a 401. Nothing else breaks.
    KS_TOKEN=<session token, revocable>
    KS_BASE=https://keyshield-production.up.railway.app
    How it works

    Store a key once. Hand out tokens instead.

    One vault with two ways in: a dashboard and browser extension for you, and an SDK, CLI and REST API for your agents.

    1. Save the key once

      The extension saves it from the provider's page, or you paste it in the dashboard. The Device Vault encrypts on your device.

    2. Give the agent a token

      Copy a session token, or register the agent's ed25519 key so it can sign in by itself.

    3. Proxy checks every call

      The token and its revocation status are checked, then the proxy looks up your key for this request.

    4. Provider gets your key

      The call is forwarded with your key and the key is dropped. Revoke the token any time.

    02 · Tokens

    Scoped session tokens

    Agents get a bearer token scoped to a provider, with an expiry. The raw sk- key never enters the agent's process.

    03 · Revocation

    Revoked on the next request

    Tokens are checked on every proxy call, with no cache window. Revoke from the dashboard, the API or Claude, and the next call fails.

    04 · Agents

    Agents sign in by themselves

    Register an agent's ed25519 public key. It signs a server challenge to get its own token, and the server never stores its private key.

    A Device Vault on your device

    Passkey PRF output goes through HKDF-SHA256 to an AES-256-GCM key that can't be exported. The sync server stores only ciphertext. MCP server, Python SDK and CLI are in the repo too.

    Security model

    What each part can see.

    Agents never see your keys. This is exactly where each copy lives, including the one on the server.

    Your device
    The plaintext keyThe Device Vault encrypts it locally with WebAuthn PRF → HKDF-SHA256 → AES-256-GCM.
    Device Vault sync
    Ciphertext onlyThe sync worker stores { ciphertext, nonce, tag }. Without your device credential it can't decrypt them.
    Hosted vault
    A server-side copyKeys saved by the extension or on the Vault page go to the control API (/manage/store), so /vproxy can add them to calls. Whoever runs that server can read them. Self-host to keep it on yours, or call /proxy and send the key from your device in X-Upstream-API-Key.
    Agent process
    A session tokenNo sk-, sk-ant- or gsk_ material. Each token can be revoked on its own.
    Proxy
    The key, for one requestChecks the token and revocation, adds the key, forwards the call, and never hands the key back to the agent.
    Provider
    A normal API callMade with your key. Nothing about the provider's API changes.
    Guardrails
    Limits on runaway agentsPer-session spend caps per second and per minute. Repeated empty or 5xx upstream responses freeze the session. Sign-in routes are rate-limited, and every proxy path needs a valid session.
    Tested on failure paths
    Bankrun security
    Clawback only after the dispute window. Closed accounts can't come back, and concurrent settles can't double-claim.npm run test:bankrun
    Fuzz invariants
    Random instruction sequences keep spend within bounds. Unauthorized or revoked signers leave state unchanged.cargo test --test fuzz_invariants
    Fault injection
    502/504, dropped TCP, empty 200 and truncated JSON give no fulfilment proof, so nothing settles.npm run test:fault
    End-to-end
    Passkey-derived session → proxy → on-chain stream, as a dry run with no spending.npm run live:e2e:dry
    Known limits
    • Keys saved through the extension or /manage/store are stored server-side, not end-to-end encrypted. Self-host if you don't want them on a hosted server.
    • KeyShield only protects calls that go through the proxy. It can't add a key to a binary that never calls it.
    • The decrypted key is in the proxy's memory while it handles a request. secrecy/zeroize hardening is planned, not yet a dependency.
    • On-chain metering runs on Solana devnet only. The spec is v0.1 and the SDK is alpha.
    • No latency numbers are published until they're measured in a named production environment.
    Quickstart

    First proxied call in five minutes.

    1. Open the appSign in at app.ks.aileena.xyz with a passkey, or run it yourself.
    2. Save a provider keyAdd an OpenRouter key under Vault. Its :free models cost nothing.
    3. Copy your tokenOpen Developer, copy the session token and set it as KS_TOKEN.
    4. Make the callUse any snippet here. Your code only ever holds KS_TOKEN.
    export KS_TOKEN="<paste from Developer>"
export KS_BASE="https://keyshield-production.up.railway.app"

curl -sS -X POST "$KS_BASE/vproxy/openrouter/api/v1/chat/completions" \
  -H "Authorization: Bearer $KS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"model":"nvidia/nemotron-3-ultra-550b-a55b:free",
       "messages":[{"role":"user","content":"ping"}]}'
    import os
from openai import OpenAI

# api_key is your KeyShield session, not the OpenRouter key.
client = OpenAI(
    base_url=os.environ["KS_BASE"] + "/vproxy/openrouter/api/v1",
    api_key=os.environ["KS_TOKEN"],
)

reply = client.chat.completions.create(
    model="nvidia/nemotron-3-ultra-550b-a55b:free",
    messages=[{"role": "user", "content": "ping"}],
)
print(reply.choices[0].message.content)
    import OpenAI from "openai";

// apiKey is your KeyShield session, not the OpenRouter key.
const client = new OpenAI({
  baseURL: process.env.KS_BASE + "/vproxy/openrouter/api/v1",
  apiKey: process.env.KS_TOKEN,
});

const reply = await client.chat.completions.create({
  model: "nvidia/nemotron-3-ultra-550b-a55b:free",

console.log(reply.choices[0].message.content);

    FAQ

    Questions people ask first.

    Can KeyShield read my API keys?

    That depends on which vault holds them. Keys in the Device Vault are encrypted on your device, and the sync server stores only ciphertext. Keys saved through the extension or the Vault page go to the control API so the proxy can add them to calls, so whoever runs that server can read them. On the hosted instance, that's KeyShield.

    If you don't want that, self-host the stack, or call /proxy and send the key from your device with each request in X-Upstream-API-Key. Either way, the proxy never passes the key to the agent.

    Is it free?

    Yes. KeyShield is open source under the MIT license, and you can run the whole stack on your own machine or servers. You still pay your model providers as usual. Their free tiers, like OpenRouter's :free models, work through KeyShield.

    What happens if an agent leaks its token?

    Revoke it under Sessions or Agents, through POST /sessions/{prefix}/revoke or DELETE /agents/{id}, or ask Claude through the MCP server. The token stops working on its next request. Your provider key and your other agents keep working, because the leaked token never contained the key.

    Which providers and clients work?

    There are proxy paths for OpenAI, Anthropic, OpenRouter, Groq, Mistral, Cohere and Helius (Solana RPC). Any client that takes a base URL and a bearer token works, including the OpenAI SDK, LangChain, CrewAI, AutoGen and the Vercel AI SDK. Streaming responses pass through as SSE.

    Do I need a crypto wallet?

    No. Sign in and unlock with a passkey. A Solana wallet is optional, either for signing in or for the experimental per-call metering, which currently runs on devnet.

    How is this different from 1Password CLI or HashiCorp Vault?

    Those tools hand the secret to your process, for example through environment variables with op run. KeyShield never does that. The agent gets a token that can be revoked on its own and is only valid through the proxy, while the raw key stays in the vault and the proxy. If you do want op run-style injection, the CLI's keyshield run does it too.

    Is it production-ready?

    It's early. The protocol spec is v0.1 and the Python SDK is alpha. Security and fault-injection tests run in CI, but read the known limits and the security write-up before you trust it with high-value keys.
